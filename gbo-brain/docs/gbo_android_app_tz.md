# ТЗ: Android-приложение «GBO HEATER»

Собрать нативное Android-приложение для головного устройства (магнитолы)
и телефона. Приложение управляет подогревателем редуктора ГБО на ESP32
по локальной сети.

Результат: собранный **APK**, готовый к установке. Не WebView-обёртка —
нативный интерфейс на Kotlin.

---

## 1. Технические требования

- Kotlin, Android Studio, Gradle
- minSdk 21 (магнитолы часто на Android 5–9), targetSdk 34
- Без внешних тяжёлых зависимостей. HTTP — OkHttp или HttpURLConnection,
  JSON — org.json (встроенный)
- График рисовать на Canvas вручную, без библиотек
- Ориентация: portrait и landscape, обе рабочие
- Приложение должно работать **без интернета** — только локальная сеть

### Разрешения и сеть

```xml
<uses-permission android:name="android.permission.INTERNET"/>
<uses-permission android:name="android.permission.ACCESS_NETWORK_STATE"/>
<uses-permission android:name="android.permission.ACCESS_WIFI_STATE"/>
```

Обязательно разрешить открытый HTTP (плата работает без TLS):

```xml
android:usesCleartextTraffic="true"
```

## 2. Протокол обмена с платой

Плата — HTTP-сервер на порту 80. Три эндпоинта.

### GET /api — опрашивать раз в секунду

Возвращает JSON:

```json
{
  "red": 24.5,        // температура редуктора, °C (или null если датчик неисправен)
  "p1": 23.8,         // пластина 1, °C (или null)
  "p2": 24.1,         // пластина 2, °C (или null)
  "rawR": 2150,       // сырое значение АЦП датчика редуктора, 0..4095
  "raw1": 118,        // сырое АЦП пластины 1
  "raw2": 121,        // сырое АЦП пластины 2
  "duty": 0,          // текущая скважность, 0..100 %
  "vbat": 12.4,       // напряжение бортсети, В
  "sp": 75,           // уставка по пластинам, °C
  "pwr": 80,          // потолок мощности, %
  "cut": 60,          // отсечка по редуктору, °C
  "relay": false,     // состояние реле K1
  "warm": false,      // редуктор прогрет, подогрев не нужен
  "uv": false,        // просадка бортсети, нагрев временно снят
  "latched": false,   // авария с защёлкой
  "state": 0,         // 0 ожидание, 1 запуск, 2 нагрев, 3 останов
  "fault": 0,         // код аварии 0..9
  "ftext": "",        // текстовая расшифровка аварии
  "log": ["00:01:23  подогрев запущен", "..."]   // до 20 строк
}
```

### GET /set?sp=85&pw=100&ct=60 — записать уставки

Все три параметра можно слать вместе или по отдельности.
Плата сама ограничивает диапазоны и сохраняет в энергонезависимую память.
Ответ: `ok`

Диапазоны:
- `sp` 60...130, шаг 1
- `pw` 20...100, шаг 5
- `ct` 40...80, шаг 1

### GET /reset — сбросить защёлку аварии

Ответ `ok` — сброшено. Ответ `hot` — отказ, пластина ещё горячее 150 °C,
показать пользователю сообщение и не сбрасывать.

## 3. Подключение к плате

Плата работает в двух режимах, приложение должно поддерживать оба.

**Режим STA.** Плата подключена к точке доступа магнитолы, получает
адрес по DHCP. Адрес заранее неизвестен.

**Режим AP.** Плата подняла свою сеть `GBO-Heater`, пароль `12345678`,
её адрес всегда `192.168.4.1`.

Логика подключения при старте приложения:

1. Взять сохранённый в SharedPreferences адрес, если есть. Проверить
   запросом `/api` с таймаутом 1500 мс.
2. Если не ответил — попробовать `192.168.4.1`.
3. Если не ответил — просканировать текущую подсеть: взять адрес
   устройства, перебрать `x.x.x.1` ... `x.x.x.254`, на каждый послать
   `/api` с таймаутом 300 мс, в 20 параллельных потоках. Сканирование
   всей подсети должно укладываться в 5 секунд.
4. Первый ответивший адрес сохранить в SharedPreferences.
5. Если не нашли — показать экран «ПЛАТА НЕ НАЙДЕНА» с кнопкой
   «ПОВТОРИТЬ ПОИСК» и полем ручного ввода IP.

При потере связи в процессе работы: не закрывать экран, а переключить
индикатор в статус OFFLINE и продолжать попытки раз в 3 секунды.
Последние полученные значения оставить на экране, приглушив их цветом.

## 5. Экран

Один основной экран, сверху вниз:

### 5.1 Шапка

Слева `GBO HEATER` жёлтым, 17 sp, жирный, межбуквенный интервал.
Справа индикатор: `● ONLINE` зелёным либо `● OFFLINE` красным.

### 5.2 Строка статуса

Широкая плашка на всю ширину, 13 dp внутренних отступов, текст по центру,
жирный, с межбуквенным интервалом. Приоритет отображения сверху вниз:

| Условие | Текст | Фон / текст |
|---|---|---|
| `latched` | `АВАРИЯ {fault} · {FTEXT в верхнем регистре}` | `#2A0E0E` / `#FF4D4D` |
| `uv` | `ПРОСАДКА · НАГРЕВ СНЯТ` | `#221D0A` / `#FFD23F` |
| `warm` | `РЕДУКТОР ПРОГРЕТ · ОБЕСТОЧЕНО` | `#221D0A` / `#FFD23F` |
| `state == 2` | `НАГРЕВ` | `#0E2A18` / `#3DDC84` |
| `state == 1` | `ЗАПУСК` | `#0E2A18` / `#3DDC84` |
| иначе | `ОЖИДАНИЕ` | `#221D0A` / `#FFD23F` |

### 5.3 График

Высота 190 dp, фон `#121922`, рамка.

- Сетка: 4 горизонтальные и 5 вертикальных линий цветом `#1A2530`,
  толщина 1 px
- Три трассы толщиной 3 px: редуктор `#FF4D4D`, пластина 1 `#22D3EE`,
  пластина 2 `#FFD23F`
- Вертикальный масштаб фиксированный: 0...280 °C
- Буфер 300 точек, одна точка в секунду, то есть пять минут истории.
  Старые точки выдвигаются слева
- Значения `null` рисовать как разрыв линии, а не как ноль

Под графиком легенда: три подписи с цветными отрезками 14×3 px,
текст 11 sp цветом `#6B7C8D`: `РЕДУКТОР`, `ПЛАСТИНА 1`, `ПЛАСТИНА 2`.

### 5.4 Показания, две строки по три карточки

Первая строка:

| Заголовок | Значение | Подпись снизу |
|---|---|---|
| `РЕДУКТОР` | `red`, одна цифра после запятой, цвет `#FF4D4D` | `ADC {rawR}` |
| `ПЛАСТИНА 1` | `p1`, цвет `#22D3EE` | `ADC {raw1}` |
| `ПЛАСТИНА 2` | `p2`, цвет `#FFD23F` | `ADC {raw2}` |

Вторая строка:

| Заголовок | Значение |
|---|---|
| `БОРТСЕТЬ` | `{vbat} В` |
| `МОЩНОСТЬ` | `{duty} %` синим, снизу полоска заполнения высотой 6 dp |
| `РЕЛЕ K1` | `ЗАМКНУТО` зелёным либо `РАЗОМКНУТО` серым |

Заголовки карточек 10 sp цветом `#6B7C8D` с межбуквенным интервалом,
значения 25 sp жирным, подписи ADC 10 sp цветом `#3F4E5C`.

При `null` в температуре показывать `--`.

### 5.5 Блок настройки

Заголовок `НАСТРОЙКА`, 11 sp, `#6B7C8D`.

Три ползунка, каждый строкой: слева короткое имя, по центру SeekBar,
справа значение крупно и единица измерения.

| Имя | Цвет | Параметр | Диапазон | Шаг | Единица |
|---|---|---|---|---|---|
| `SP` | `#22D3EE` | уставка по пластинам | 60...130 | 1 | °C |
| `PWR` | `#2B6CFF` | потолок мощности | 20...100 | 5 | % |
| `CUT` | `#40D3EE` отсечка жёлтым `#FFD23F` | отсечка по редуктору | 40...80 | 1 | °C |

Поведение ползунков:

- Во время перетаскивания значение справа обновляется мгновенно,
  на плату **ничего не отправляется**
- Отправка `/set` — только по отпусканию пальца (`onStopTrackingTouch`)
- Пока пользователь держит ползунок и ещё 600 мс после отпускания,
  входящие значения из `/api` **не должны** перезаписывать положение
  ползунка. Иначе его будет дёргать назад на каждом опросе
- После успешной отправки значения снова синхронизируются с платой

Ползунок: дорожка 4 dp цветом `#1E2A36`, бегунок круглый 24 dp
в цвет параметра, с обводкой 2 dp цветом фона.

### 5.6 Кнопка сброса

На всю ширину, 15 dp отступов, текст `СБРОС АВАРИИ`, фон `#2A0E0E`,
текст `#FF4D4D`, рамка `#5A2020`.

- Активна только когда `latched == true`, иначе неактивна и серая
- По нажатию: запрос `/reset`. Ответ `hot` — показать Toast
  «Пластина ещё горячая, сброс после остывания ниже 150 °C»

### 5.7 Журнал

Прокручиваемый блок высотой 180 dp, фон `#121922`, рамка, моноширинный
текст 11 sp цветом `#6B7C8D`. Показывать массив `log` как есть, новые
строки снизу, автопрокрутка вниз при появлении новой строки.

## 6. Поведение приложения

- Опрос `/api` раз в секунду, пока экран активен. В `onPause` опрос
  останавливать, в `onResume` возобновлять
- Держать экран включённым, пока приложение на переднем плане
  (`FLAG_KEEP_SCREEN_ON`) — на магнитоле это важно
- При аварии (`latched` стал true) — один короткий вибросигнал, если
  устройство его поддерживает
- Никаких диалогов при старте, никаких настроек подключения на первом
  экране. Приложение должно открываться сразу в рабочем режиме
- Пользователь не должен видеть IP-адреса, JSON, коды HTTP. Адрес платы
  показывать только на экране «плата не найдена»

## 8. Что проверить перед выдачей

1. Приложение запускается и находит плату в обоих режимах, STA и AP
2. При выключении платы статус переходит в OFFLINE, приложение не падает
3. При включении обратно связь восстанавливается сама, без перезапуска
4. Ползунок не дёргается назад во время перетаскивания
5. Уставки, выставленные в приложении, сохраняются после перезагрузки
   платы (проверяется чтением `/api` — значения `sp`, `pwr`, `cut`
   должны остаться теми же)
6. График не ломается при появлении `null` в температуре
7. Кнопка сброса неактивна, когда аварии нет
