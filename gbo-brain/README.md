# Мозги для ГБО — подогреватель редуктора на ESP32 + Android-приложение

Отдельный проект, к трёхканальному генератору отношения не имеет. Лежит в этом
же репозитории, чтобы всё хозяйство было в одном месте.

Папка называется `gbo-brain`, а не «Мозги для ГБО», потому что Gradle не собирает
проекты, в пути которых есть кириллица или пробелы — на этом уже спотыкались с
`pwmgen`.

## Что где лежит

| Папка | Содержимое |
|---|---|
| `app/` | Исходники Android-приложения **GBO HEATER**, пакет `ru.gbo.heater` |
| `app/src/main/assets/index.html` | Весь интерфейс приложения |
| `firmware/` | Прошивка платы `gbo_heater_v3.ino` (ESP32, Arduino IDE) |
| `docs/` | Техническое задание на приложение |

## Как собрать APK

Сборка идёт в GitHub Actions, воркфлоу `.github/workflows/build-gbo.yml`.
Запускается при пуше в `main`, если менялось что-то в `gbo-brain/`, либо вручную
на вкладке **Actions** → **Build GBO APK** → **Run workflow**.

Готовый файл — в артефактах сборки, `gbo-heater-debug`.

Локально (нужен JDK 17 и Android SDK):

```
cd gbo-brain
./gradlew assembleDebug
```

APK окажется в `app/build/outputs/apk/debug/app-debug.apk`.

## Как приложение находит плату

1. Адрес из прошлого запуска (сохраняется в SharedPreferences), проверка 1,5 с
2. `192.168.4.1` — плата в режиме своей точки доступа `GBO-Heater` / `12345678`
3. Перебор текущей подсети `x.x.x.1…254` в 20 потоков по 300 мс на адрес

Если не нашлась — экран «ПЛАТА НЕ НАЙДЕНА» с кнопками «повторить поиск» и
«ввести адрес вручную». Адрес можно вбить в любой момент: долгое нажатие на
кнопку `WiFi` в левом столбце.

Связь оборвалась — приложение не закрывает экран: индикатор уходит в `OFFLINE`,
последние показания остаются приглушёнными, попытки идут раз в 3 с. Если плата
не отвечает три раза подряд, поиск запускается заново — адрес мог смениться
после переподключения к точке доступа.

## Обмен с платой

Плата — HTTP-сервер на порту 80, без TLS и без CORS-заголовков. Поэтому запросы
делает Java, а в WebView результат приезжает через `evaluateJavascript`; сама
страница в сеть не ходит.

| Запрос | Назначение |
|---|---|
| `GET /api` | Опрос раз в секунду: температуры, АЦП, мощность, бортсеть, уставки, журнал |
| `GET /set?sp=&pw=&ct=` | Уставки: порог по пластинам 60…130 °C, потолок мощности 20…100 %, отсечка по редуктору 40…80 °C |
| `GET /reset` | Сброс защёлки аварии. Ответ `hot` — пластина ещё горячее 150 °C, сброса не будет |

## Интерфейс

Тёмная приборная панель в гамме `pwmgen`: фон `#040408`, рамки `#1a2540`,
жёлтый `#ffc300`, синий `#00aaff`, бирюзовый `#00ffee`, зелёный `#00ff88`,
красный `#ff3333`.

Слева столбец кнопок — переключение между показаниями, уставками и журналом,
кнопка сброса аварии и кнопка связи. Справа график на пять минут истории
(300 точек, шкала 0…280 °C, три трассы: редуктор, пластина 1, пластина 2)
и поверх него плашка состояния.

Ползунки уставок отправляют значение на плату только по отпусканию пальца.
Пока ползунок держат и ещё 600 мс после — данные с платы не трогают его
положение, иначе его дёргало бы назад на каждом опросе.
